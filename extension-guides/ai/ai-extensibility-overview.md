# VS Code 中的 AI 扩展性概览（AI extensibility in VS Code）

> 原文：[AI extensibility in VS Code](https://code.visualstudio.com/api/extension-guides/ai/ai-extensibility-overview)
> 源文件：`microsoft/vscode-docs` → `api/extension-guides/ai/ai-extensibility-overview.md`（DateApproved: 10/7/2026）

> VS Code 包含强大的 AI 功能，可以增强编码体验：
>
> - **代码补全**：在你输入时提供行内代码建议
> - **智能体模式（Agent mode）**：让 AI 使用专门的工具，自主地规划和执行开发任务
> - **聊天（Chat）**：让开发者通过聊天界面，用自然语言提问或修改代码库
> - **智能操作（Smart actions）**：在编辑器各处集成的、由 AI 增强的常见开发任务操作
>
> 你可以扩展和定制每一项内置能力，打造满足用户特定需求的 AI 体验。

这一系列共 9 篇，介绍扩展如何接入 VS Code 的 AI 功能。本篇是**总览**，帮你判断该用哪种方式；后面的几篇分别详细讲解每种方式。

**几个基本概念：**

| 概念 | 说明 |
|---|---|
| **语言模型**（Language Model） | 就是大语言模型（LLM），比如 GPT、Claude 等。给它一段文字（提示词），它生成一段回复 |
| **聊天视图**（Chat） | VS Code 中与 AI 对话的面板 |
| **询问模式**（Ask mode） | 聊天的一种模式：你问，AI 答 |
| **智能体模式**（Agent mode） | 聊天的另一种模式：你给出一个任务，AI 自己决定调用哪些**工具**（读文件、搜索、运行命令……），一步步完成任务 |
| **工具**（Tool） | AI 可以调用的一个功能。比如“查询数据库”“读取某个文件”。AI 根据需要决定什么时候调用、传什么参数 |

<a id="why-extend-ai-in-vs-code"></a>
## 为什么要在 VS Code 中扩展 AI？（Why extend AI in VS Code?）

> 在你的扩展中加入 AI 能力，能给用户带来以下好处：
>
> - **智能体模式中的领域知识**：让智能体模式能够访问你们公司的数据源和服务
> - **增强的用户体验**：提供针对你的扩展所在领域量身定制的智能辅助
> - **领域专精**：创建特定于某种编程语言、框架或领域的 AI 功能
> - **扩展聊天能力**：向聊天界面添加专门的工具或助手，实现更强大的交互
> - **提高开发者的生产力**：用 AI 能力增强调试、代码审查或测试等常见的开发任务

举个例子：通用的 AI 不知道你们公司内部的接口文档、数据库结构、部署流程。你的扩展可以提供一个“查询内部接口文档”的工具，智能体模式在回答问题或写代码时，就会自动调用它，给出符合你们公司实际情况的结果。

<a id="extend-the-chat-experience"></a>
## 扩展聊天体验（Extend the chat experience）

扩展聊天有三种方式，先看对比，再逐个介绍：

| 方式 | 用户如何使用 | 在哪里运行 | 能否使用 VS Code API |
|---|---|---|---|
| 语言模型工具 | 智能体模式自动调用，或在提示词中用 `#工具名` 引用 | 扩展宿主（你的扩展中） | 能 |
| MCP 工具 | 智能体模式自动调用 | VS Code 之外（本地进程或远程服务） | 不能 |
| 聊天参与者 | 在聊天中用 `@参与者名` 提问 | 扩展宿主（你的扩展中） | 能 |

<a id="language-model-tool"></a>
### 语言模型工具（Language model tool）

> 语言模型工具让你可以用特定领域的能力扩展 VS Code 中的智能体模式。在智能体模式中，这些工具会根据用户的聊天提示词被自动调用，执行专门的任务，或者从某个数据源或服务中获取信息。用户也可以在聊天提示词中通过 #-提及（#-mentioning）工具，显式地引用这些工具。
>
> 要实现语言模型工具，请在你的 VS Code 扩展中使用[语言模型工具 API](./tools.md)。语言模型工具可以访问所有的 VS Code 扩展 API，并与编辑器深度集成。
>
> **主要优点**：
>
> - 作为自主编码工作流的一部分，提供特定领域的能力
> - 由于工具运行在扩展宿主进程中，它的实现可以使用 VS Code API
> - 可以通过 Visual Studio 扩展市场方便地分发和部署
>
> **主要考虑因素**：
>
> - 远程部署需要扩展自己实现客户端与服务器之间的通信
> - 要在不同的工具之间复用，需要模块化的设计和实现

<a id="mcp-tool"></a>
### MCP 工具（MCP tool）

> 模型上下文协议（Model Context Protocol，MCP）工具提供了一种使用标准化协议、把外部服务与语言模型集成起来的方式。在智能体模式中，这些工具会根据用户的聊天提示词被自动调用，执行专门的任务，或者从外部数据源获取信息。
>
> MCP 工具运行在 VS Code 之外，要么在用户的电脑上本地运行，要么作为远程服务运行。用户可以通过 JSON 配置添加 MCP 工具，VS Code 扩展也可以通过代码配置它们。你可以使用各种语言的 SDK 和部署方式来实现 MCP 工具。
>
> 由于 MCP 工具运行在 VS Code 之外，它们无法访问 VS Code 扩展 API。
>
> **主要优点**：
>
> - 作为自主编码工作流的一部分，添加特定领域的能力
> - 可以选择本地部署或远程部署
> - 可以在其他 MCP 客户端中复用 MCP 服务器
>
> **主要考虑因素**：
>
> - 无法访问 VS Code 扩展 API
> - 分发和部署需要用户设置 MCP 服务器

**MCP 是什么？** MCP 是一个开放的标准协议，规定了“AI 应用如何调用外部工具”。和本指南中多次出现的 LSP（语言服务器协议）、DAP（调试适配器协议）思路一样：定义一个统一的协议，一个 MCP 服务器写好之后，VS Code、Claude Desktop 等所有支持 MCP 的 AI 应用（MCP 客户端）都能使用它。

**语言模型工具和 MCP 工具，功能上很像，区别在于运行的位置：**

```text
语言模型工具：  VS Code ── 扩展宿主（你的扩展中的工具代码，能调用 vscode API）
MCP 工具：      VS Code ── MCP 协议 ── MCP 服务器（独立进程或远程服务，不能调用 vscode API）
```

<a id="chat-participant"></a>
### 聊天参与者（Chat participant）

> 聊天参与者是专门的助手，让用户可以用特定领域的专家来扩展询问模式。在聊天中，用户可以通过 @-提及来调用一个聊天参与者，并传入一段关于某个特定主题或领域的自然语言提示词。聊天参与者负责处理整个聊天交互过程。
>
> 要实现聊天参与者，请在你的 VS Code 扩展中使用[聊天 API](./chat.md)。聊天参与者可以访问所有的 VS Code 扩展 API，并与编辑器深度集成。
>
> **主要优点**：
>
> - 控制端到端的交互流程
> - 由于运行在扩展宿主进程中，可以访问 VS Code 扩展 API
> - 可以通过 Visual Studio 扩展市场方便地分发和部署
>
> **主要考虑因素**：
>
> - 远程部署需要扩展自己实现客户端与服务器之间的通信
> - 要在不同的工具之间复用，需要模块化的设计和实现

**工具和聊天参与者的根本区别：谁在“主导”对话。**

| | 工具 | 聊天参与者 |
|---|---|---|
| 谁决定什么时候调用 | AI（智能体）根据需要决定 | 用户用 `@名字` 主动调用 |
| 扮演的角色 | AI 手中的一件“工具” | 一个独立的“专家”，自己负责回答 |
| 对回答过程的控制 | 只提供数据，回答由 AI 组织 | 完全控制：用什么提示词、调用哪个模型、如何展示回复 |
| 例子 | “查询 Jira 中的某个工单” | `@vscode`：专门回答 VS Code 使用问题的助手 |

<a id="build-your-own-ai-powered-features"></a>
## 构建你自己的 AI 功能（Build your own AI-powered features）

> VS Code 让你可以通过代码直接访问 AI 模型，在扩展中创建自定义的 AI 功能。这种方式让你可以构建特定于编辑器的交互，使用 AI 能力，而不依赖聊天界面。
>
> 要直接使用语言模型，请在你的 VS Code 扩展中使用[语言模型 API](./language-model.md)。你可以把这些 AI 能力融入任何扩展功能中，例如代码操作、悬停提供者、自定义视图等。
>
> **主要优点**：
>
> - 把 AI 能力集成到现有的扩展功能中，或者构建新功能
> - 由于运行在扩展宿主进程中，可以访问 VS Code 扩展 API
> - 可以通过 Visual Studio 扩展市场方便地分发和部署
>
> **主要考虑因素**：
>
> - 要在不同的体验之间复用，需要模块化的设计和实现

前面三种方式都是“往聊天里加东西”，而这种方式是“**在聊天之外用 AI**”。比如：

- 悬停在一段代码上，显示 AI 生成的解释；
- 在右键菜单中加一个“用 AI 生成单元测试”的命令；
- 在编辑器中用装饰标出 AI 认为可能有问题的代码（见 [语言模型 API 教程](./language-model-tutorial.md)）。

关键的一点：**扩展不需要自己去申请 AI 服务的账号和密钥**。语言模型 API 使用的是用户在 VS Code 中已经能用的模型（比如用户订阅的 GitHub Copilot 中提供的模型），调用前会征得用户同意。

<a id="decide-which-option-to-use"></a>
## 决定使用哪种方式（Decide which option to use）

> 在为你的 VS Code 扩展选择合适的 AI 扩展方式时，可以参考以下准则：

| 选择 | 适合的情况 |
|---|---|
| **语言模型工具** | 你想用专门的能力扩展 VS Code 中的聊天；你希望在智能体模式中根据用户意图被自动调用；你需要访问 VS Code API，与 VS Code 深度集成；你希望通过 VS Code 扩展市场分发你的工具 |
| **MCP 工具** | 你想用专门的能力扩展 VS Code 中的聊天；你希望在智能体模式中根据用户意图被自动调用；你不需要与 VS Code API 集成；你的工具需要在不同的环境中工作（不只是 VS Code）；你的工具应该在远程或本地运行 |
| **聊天参与者** | 你想用一个具有领域专业知识的专门助手来扩展询问模式；你需要定制整个交互流程和回复行为；你需要访问 VS Code API，与 VS Code 深度集成；你希望通过 VS Code 扩展市场分发你的工具 |
| **语言模型 API** | 你想把 AI 能力集成到现有的扩展功能中；你正在构建聊天界面之外的界面体验；你需要通过代码直接控制对 AI 模型的请求 |

一个简单的判断流程：

```text
要在聊天界面中使用吗？
  ├─ 否 → 语言模型 API
  └─ 是 → 是让 AI 自动调用的“工具”，还是用户 @ 的“助手”？
            ├─ 助手 → 聊天参与者
            └─ 工具 → 需要调用 VS Code API 吗？或者只在 VS Code 中使用吗？
                      ├─ 是 → 语言模型工具
                      └─ 否，还想给其他 AI 应用用 → MCP 工具
```
